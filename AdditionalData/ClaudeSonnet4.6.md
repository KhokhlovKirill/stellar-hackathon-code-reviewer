### 📋 Подробный план реализации

#### Стек технологий

**Backend:** Python (FastAPI) — быстро, async-нативно, идеально для webhook-обработки. **LLM:** Anthropic Claude API (claude-sonnet) — лучший в code reasoning, минимум ложных срабатываний. **БД:** PostgreSQL (аудит-лог) + Redis (кеш диффов и сессии диалога). **Очереди:** Celery + Redis — параллельный анализ нескольких PR одновременно. **Инфра:** Docker Compose для демо, легко масштабируется.

---

#### Фазы реализации (хакатон: 24–48 ч)

**Фаза 1 — Ядро (первые 8 часов).** Webhook-сервер для GitHub/GitLab. Парсер диффов с фильтрацией нерелевантных файлов (`.md`, `.gitignore`, картинки, локали). Базовый промпт-конструктор. Публикация комментариев через API. Это MVP — бот уже работает.

**Фаза 2 — Интеллект (8–20 часов).** Детектор секретов (паттерны + энтропийный анализ Shannon для токенов). Чекер зависимостей через PyPI JSON API и OSV (Open Source Vulnerabilities) database. Механизм approve/decline. Логирование в PostgreSQL.

**Фаза 3 — Киллер-фичи (20–40 часов).** Реализация всего списка ниже — именно они принесут победу.

### 🔥 Киллер-фичи (то, что удивит экспертов)

#### 1. Risk Score с объяснением — «светофор» в PR

Вместо простого «найдена уязвимость» бот выставляет числовой Risk Score от 0 до 100 с цветовой индикацией и детальным breakdown: `SQLi: +40, hardcoded secret: +35, outdated dep: +15`. Эксперты увидят зрелый продуктовый подход — не просто флаги, а приоритизация.

#### 2. Диалог прямо в комментариях GitLab/GitHub

Разработчик отвечает боту `@secbot why is this SQL injection?` — и бот отвечает контекстно, объясняет механизм атаки, приводит PoC-пример эксплойта и предлагает исправленный вариант. Сессия сохраняется в Redis. Это настоящий AI-агент, а не просто скрипт.

#### 3. Энтропийный анализ секретов

Классические regex-детекторы ловят `password = "qwerty"`, но пропускают `key = "aB3#kL9mN2pQ7rS"`. Алгоритм Шеннона вычисляет энтропию строк: высокая энтропия в присвоении переменной = вероятный токен/ключ. Ноль ложных срабатываний на обычных строках.

#### 4. Smart Context Window — бот «видит» соседние функции

Вместо анализа только изменённых строк бот запрашивает ±50 строк контекста вокруг каждого diff-чанка. Это позволяет найти уязвимости, которые проявляются через взаимодействие нескольких функций, — и резко снижает False Positive rate.

#### 5. Автоматический pull request с фиксом

Если бот нашёл хардкод пароля или несекьюрную зависимость, он не просто комментирует — он **сам создаёт новый PR** с исправлением: переменная уходит в `.env`, зависимость обновляется до patched-версии. Эксперты обычно такого не ожидают от хакатон-проекта.

#### 6. Retro-анализ репозитория по команде

Администратор пишет `@secbot scan full` — и бот в фоне прогоняет весь репозиторий по той же логике, что и для новых PR, генерируя Summary Report в виде markdown-файла прямо в репо. Это мощная демо-точка: показываешь экспертам, сколько проблем нашлось в реальном проекте.

#### 7. Обучение на False Positives команды

Если разработчик отвечает `@secbot false positive, this is test data` — бот фиксирует это в PostgreSQL. Через несколько итераций в промпт автоматически добавляются team-specific исключения (`не флагировать паттерны в директории /tests/fixtures`). Система становится умнее с каждым ревью.

#### Структура промпта (критически важно для качества)

Вот скелет системного промпта — от него зависит 80% качества анализа:

```
You are a security code reviewer. Analyze ONLY the provided git diff.

RULES:
- Report ONLY confirmed vulnerabilities, never speculation
- For each finding: severity (critical/high/medium/low), CWE ID, affected line, explanation, fix snippet
- If no vulnerabilities found, respond: {"findings": []}
- Do NOT flag: test files with mock data, commented-out code, documentation

CONTEXT: {language}, {framework}, {file_path}
DIFF:
{diff_chunk}

Respond ONLY in JSON. No markdown, no preamble.
```

Строгий JSON-ответ позволяет парсить результат без LLM-галлюцинаций и делает систему надёжной.

#### Почему это выиграет

Большинство команд на таких хакатонах делают «ChatGPT, посмотри мой код» с веб-интерфейсом. Ваш проект — это полноценный production-ready агент: работает автоматически на реальных воркфлоу, обучается на обратной связи команды, сам создаёт фиксы и объясняет уязвимости в контексте конкретного кода. Показать его на живом репозитории с реальным PR — самый убедительный демо-сценарий.
